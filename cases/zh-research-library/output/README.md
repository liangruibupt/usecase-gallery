- 检索与访问日期：2026-10-23（检索人：资料组）

## 一、范围与来源规则

1. **主题**：中小企业数字化转型。
2. **允许来源**：国务院、中国政府网、工业和信息化部及部属平台、国家数据局、地方政府官网。
3. **搜索引擎结果**：只用于发现线索，必须回到原始页面核验后才能收录。
4. **核验字段**：标题、文号、发布机构、成文日期、发布日期、页面链接、访问日期，均以原始页面或附件所载为准。
   - 页面未显示的字段一律填“页面未显示”或“记录未显示”。
   - 不依据网址路径、检索摘要或第三方报道推断补写。
5. **不提供结论**：本库不提供政策合规结论。
   - “历史文件”“时效已过”等标记，只反映文件自身载明的替代、废止条款或期限与访问日期的比较，不代表对文件效力的判断。

## 四、归档文件命名规则

基本格式：`成文日期_发布机构_文件标题_附件名.扩展名`

1. **成文日期**：写为 `YYYYMMDD`。
   - 页面未显示成文日期时，改用发布日期并加“发布”二字，如 `20250903发布`，以免与成文日期混淆。涉及 02、05、09、10。
   - 附件本身未显示日期时，采用所属通知的成文日期。涉及 13。
2. **发布机构**：取页面所载发布机构。页面未单列时，取页面标题中的发文机关。
3. **文件标题**：取页面标题。
   - 页面标题开头的机关名称与“发布机构”字段相同的，省略该段，例如“东川省工业和信息化厅关于印发……”记为“关于印发……”。
   - 其余文字保持原样。
4. **附件名**：取下载时的原始附件名。
   - 去掉浏览器自动添加的重名后缀，如“(1)”“(2)”，涉及 04、07。
   - 页面列出了附件序号的，按页面所列附件名写，如 13 写为“附件1申报指南”。
5. **网页正文**：没有附件、以网页正文为原件的记录，附件名写为“网页正文”，扩展名按实际保存格式（本次为 .txt）。
6. **字符处理**：标题中的英文双引号统一改为中文引号“”，以兼容 Windows 文件名，涉及 11。其他字符保持原样。
7. **排除线索**：不收录的 14、15 不按规则重命名，保留原保存名放入“排除线索/”。

## 五、catalog 字段说明

| 字段 | 说明 |
|---|---|
| 编号 | 与原始保存文件名前缀一致（00—15） |
| 原始保存文件名 / 原始附件文件名 | 下载或保存时的原名，便于回溯 |
| 归档文件名 / 归档位置 | 按第四节规则生成；用户据此重命名并放入相应文件夹 |
| 收录状态 | 见第六节 |
| 资料类型 | 政策文件、政策文件附件、转载页面、政策解读、工作通知等 |
| 页面标题 / 文件标题（正文所载） | 分别取页面标题和附件或正文中的文件名称 |
| 发文字号、发布机构、成文日期、发布日期 | 按页面或附件所载填写；“据页面标题”表示该机构取自页面标题 |
| 页面链接 / 访问日期 / 页面访问状态 | 来源页面地址、访问日期与保存记录中注明的访问状态 |
| 来源类别 | 是否属于允许来源，以及所属机构层级 |
| 时效与版本标记 | 替代、废止关系及文件所载期限 |
| 关联记录 / 对应问题编号 | 与其他记录的关系，以及 issues 表中的条目 |
| 核验说明 | 与检索记录对照的结果及其他说明 |

## 六、状态与标记定义

| 标记 | 含义 |
|---|---|
| 收录（主记录） | 来自原发机关页面的独立资料 |
| 收录（更新版本） | 文件明确载明替代某一旧版本 |
| 收录（历史文件） | 已被新版本明确替代或废止，或文件自身所载规划期已结束；保留存档 |
| 收录（重复副本） | 与某主记录内容一致的转载或转发，仅作存档 |
| 收录（解读材料） | 官方发布的解读，以原文为准 |
| 收录（附件） | 随某主记录发布的附件 |
| 不收录（非允许来源） | 来源不在允许范围内，仅作线索存于“排除线索/” |
| 待确认 | 字段缺失、信息不一致或范围需确认，详见 issues 表 |

> 说明：01 的收录状态为“主记录”，同时在“时效与版本标记”中标注其所载有效期已届满。

## 十、维护规则

1. **新增资料**：先在原页面核验，再在 catalog 末尾追加编号，按第四节规则命名并放入对应文件夹。
2. **版本更新**：新版本登记为“更新版本”，被替代的旧版本改为“历史文件”。旧版本不删除，并在 issues 表新增一条，写明替代依据（原文条款）。
3. **待确认事项**：核实后，在 issues 表“状态”列改为“已解决”，并注明依据和日期。涉及更名的，同步修改归档文件名和 catalog。
4. **链接复核**：建议定期复核。发现失效链接时在 issues 表登记，原存档保留不删。
5. **版本记录**：每次维护后在下表追加一行。
