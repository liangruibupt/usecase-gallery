# 团队任务管理 · 任务列表与详情 原型说明

版本：v2.4 评审稿（2025-06-13）
适用对象：产品、设计、研发联合评审

## 一、交付文件

| 文件 | 用途 |
| --- | --- |
| `task-board-prototype.html` | 可交互原型，单文件，断网双击即可打开 |
| `task-board-canvas.html` | 设计画布：13 个页面状态并排对照，附组件与样式规范 |
| `prototype-notes.md` | 本说明 |

- **画布源文件**：画布本身就是可继续调整的源文件。
  - 颜色、圆角、面板宽度等样式变量集中在文件顶部的 `:root`。
  - 每个状态稿由脚本里的 `SECTIONS` 配置生成。新增状态只需加一项配置，例如筛选条件、已选任务、是否打开详情。
- **一致性**：画布与原型使用同一套任务数据和样式，二者保持一致。

## 二、页面结构

**1. 顶栏**
- 产品标识和所在位置：产品团队 / v2.4 版本迭代。
- 右侧有「演示视角」切换：负责人 林知 / 成员 陈齐，评审时可对比两种角色。正式产品中不保留这个开关，视角由登录身份决定。

**2. 页头**
- 页面标题和迭代周期。
- 统计区随视角变化：
  - 负责人：全部任务、进行中、已完成、已逾期；
  - 成员：我的任务、未完成、我的逾期。

**3. 筛选工具栏**
- 搜索框：按任务名称搜索。
- 「我的任务」快捷按钮。
- 负责人下拉：附各成员的任务数。
- 状态分段：全部 / 待开始 / 进行中 / 已完成，附数量。
- 「清空筛选」：有条件生效时出现，并显示生效条件数。

**4. 任务表格**
- 列：勾选（仅负责人可见）、任务名称（含编号和类别）、负责人、状态、优先级、截止日期（含剩余或逾期天数）。

**5. 任务详情侧边面板**
- 宽 440px，从右侧滑出。
- 屏宽不小于 1101 时推开列表，列表仍可对照；761–1100 时以浮层覆盖。
- 内容依次为：字段区 → 任务说明 → 验收要求（含完成进度）→ 相关资料 → 动态。

**6. 批量操作**
- 底部浮动操作栏 → 成员选择弹层 → 结果提示（可撤销）。

**7. 手机端（宽度不超过 760）**
- 表格改为卡片。
- 详情改为全屏页。
- 批量操作栏贴底，成员选择改为底部弹层。

## 三、已完成的交互

### 1. 搜索与组合筛选
- 关键词、负责人、状态三类条件为「且」的关系，同时生效；输入时实时过滤，匹配的关键词高亮。
- 状态分段的数量会随搜索和负责人条件联动，方便预判切换后的结果数。
- 「我的任务」等同于把负责人筛选设为当前用户，两者状态同步；再点一次即取消。
- 「清空筛选」一次恢复全部条件；搜索框内的 × 只清除关键词。
- 列表上方显示「显示 X / 8 条任务」。
- 快捷键：按 `/` 聚焦搜索框。

### 2. 任务详情
- 点击任意行，或用键盘聚焦后按 Enter，打开详情；当前行显示强调条。
- 面板顶部显示该任务在当前结果中的位置（如 2 / 8），可用上一条 / 下一条切换，切换范围限于当前筛选结果。
- 点 × 或按 Esc 关闭。关闭后筛选条件、列表滚动位置保持不变，键盘焦点回到原来的行。

### 3. 批量分配（仅负责人）
- 勾选单行，或用表头复选框全选当前结果；部分勾选时表头呈半选状态。
- 勾选后底部出现操作栏，显示已选数量。如果筛选变化后有已选任务不在当前结果中，操作栏会提示「X 项不在当前结果中」。
- 点「分配给成员」打开选择弹层。弹层中每位成员都显示其未完成任务数。
- 选中成员后，弹层预告「将把 N 条任务的负责人改为 某某」；其中原本就由该成员负责的任务会单独说明。未选成员时「确认分配」不可点。
- 点「取消」、点空白处或按 Esc 都可关闭弹层，不产生变更。
- 确认后：
  - 列表中被改派的行短暂高亮，负责人列即时更新；
  - 打开中的详情同步更新负责人，并在动态顶部新增一条记录；
  - 底部提示写明变更条数，并提供「撤销」，6 秒后自动消失；
  - 撤销后负责人和动态都恢复原状；
  - 如果改派后有任务不再符合当前筛选，提示里会单独说明条数。
- 如果所选任务原本就全部由该成员负责，提示「未做变更」。

### 4. 空状态
- 搜索或筛选没有结果时，隐藏表头，显示「没有匹配的任务」。
- 列出当前生效的条件，并提供「清空筛选」主按钮。

### 5. 角色视角
- 成员视角下不显示勾选列和批量操作，统计区改为个人数据。
- 切换视角时清空已选任务；如果当前正筛选「我的任务」，会自动切换到新身份对应的人。

### 6. 手机端
- 卡片中任务名完整换行；左侧 40×40 区域用于勾选，点卡片其他位置打开详情。
- 搜索框高 40、字号 15；状态分段独占一行。
- 底部操作栏和底部弹层均预留安全区；按钮等宽，高 42。

## 四、示例数据

- 8 条 v2.4 迭代任务，覆盖需求梳理、交互原型、组件规范、评审准备和移动端检查。
- 状态：待开始 3 条、进行中 3 条、已完成 2 条。
- 优先级：高 3 条、中 3 条、低 2 条。
- 其中 1 条已逾期（T-107），1 条明天截止（T-102）。
- 成员：林知（产品负责人）、陈齐（前端研发）、周然（交互设计）、许宁（视觉设计）。
- 「今天」固定为 6 月 13 日，便于演示逾期和临期效果。
- 数据仅存在页面内存中，刷新后恢复初始状态。

## 五、需要评审确认的问题

### 产品
1. **筛选变化后已选任务的处理**：目前保留已选任务，并提示其中有几项不在当前结果中。是否改为筛选变化时自动清空已选？
2. **批量分配的通知**：是否需要通知被分配人和原负责人？通过什么渠道（站内、IM、邮件）？
3. **已完成任务能否改派**：目前允许。是否应禁止，或改派前二次提示？
4. **成员在详情里的权限**：目前详情对所有人只读。成员能否修改自己任务的状态、勾选验收项？
5. **状态筛选方式**：是否需要多选（如「待开始 + 进行中」）？默认是否隐藏已完成任务？
6. **撤销与记录**：6 秒的撤销时间是否足够？是否需要单独的操作记录页，方便事后追溯？

### 设计
7. **详情面板的打开方式**：屏宽不小于 1101 时推开列表，761–1100 时浮层覆盖，这个分界是否合适？面板是否需要支持拖拽调整宽度？
8. **红色的语义**：「高优先级」和「逾期」目前都用红色。是否需要区分，比如逾期改为标签样式？
9. **手机端入口**：手机端是否需要底部导航或「新建任务」入口？本次未涉及。
10. **详情内单条改派**：详情面板里是否提供单条改派入口？目前只能在列表中批量操作。

### 研发
11. **搜索范围**：目前只匹配任务名称。是否扩展到编号和说明？是否支持拼音或首字母搜索？
12. **状态写入 URL**：筛选条件和打开的任务是否写入 URL，以便分享链接、刷新后恢复？
13. **部分失败的反馈**：批量分配可能部分失败（权限不足、并发修改冲突），需要约定这时的反馈方式，以及撤销接口的设计。
14. **数据量增长**：团队达到 20 人、任务上百条时，负责人下拉需要加搜索，列表需要分页或虚拟滚动。
